# Native iPhone IPv4 VPN PoC

The Rust source is prepared for operator testing. Local authentication/state tests and an isolated Linux ESP-in-UDP packet round trip pass. **No actual iPhone, VPS, public certificate, systemd credential handoff or Internet egress has been tested in this cycle.** Keep the first test source-restricted and short. No deployment has been performed.

## Ubuntu preparation

1. Use Ubuntu LTS with OpenSSL 3. Install build packages `build-essential pkg-config libssl-dev ca-certificates`, runtime `openssl ca-certificates iproute2 iptables python3`, and `tcpdump` if capturing. Use the distribution's `libssl3`/`libssl3t64`; no OpenSSL legacy configuration changes. Build as an ordinary user:

   ```sh
   cd src
   cargo build --release --workspace
   cargo build --release -p vpn-auth --example provision
   ```

2. Before changing anything, keep an SSH recovery session and record existing UDP500/4500 listeners, routes/subnets, firewall backend/rules, XFRM counts and forwarding value. Check SSH, nginx, SSTP, mail and Docker before and after. Do not flush rules/state, change default policies, restart Docker/firewall services, or reuse another VPN's pool/reqid range. A running IKE server on those ports is a blocker until the operator resolves the conflict. Reserve **10.77.0.0/24**, reqids **65536–131071**, policy priority **10000**, chain names `HVPOC_IN/FWD/NAT` and one instance of this daemon; change examples consistently if any conflict exists. Check client LAN overlap too. The pool is configurable as a contiguous range within one private /24, excluding network/broadcast. Neither daemon nor scripts auto-rewrite host routes.

3. Provision a **disposable** user and a publicly trusted RSA-3072 server certificate for `vpn.hypervault.biz`. Use the existing [M3 certificate and encrypted-verifier procedure](protocol/ike-auth.md#master-key-custody-and-offline-provisioning). Build/install the reviewed provisioning binary as `/usr/local/libexec/ikev2-provision` (the `provision` example artifact), then enter a unique random 20+ character password through `systemd-ask-password` piped to it, not argv/environment. Username in the supplied profile is `m3-disposable`. All originals below are root-owned0600 in root0700 `/etc/ikev2lab`, outside Git:

   - `master.key`: independently generated 32-byte verifier-encryption key.
   - `verifiers.v1`: encrypted user record generated by provisioning example.
   - `server-key.pem`: matching RSA-3072 private key.
   - `server-chain.pem`: leaf then intermediate certificates, omit root (max four certificates / 12000 DER bytes).

   SAN must match the hostname; leaf must permit digital signatures and serverAuth, be valid and chain to the OS public trust store. Verify the actual CA's IKE suitability and native acceptance: an existing HTTPS/SSTP certificate is not automatically suitable. Do not replace with a private CA or relax hostname/usage/trust checks. The public key, certificate fingerprint and expiry can be reported; no keys/passwords/verifier plaintext/captures in Git. The existing private OpenSSL MSCHAP context must pass its RFC tests on this host; FIPS/provider restrictions are an explicit blocker.

4. Review [iphone-poc.toml](../src/config/iphone-poc.toml), replace `192.0.2.10` with the **assigned local interface** IPv4, and install it as `/etc/ikev2lab/iphone-poc.toml`. Public DNS points to the reachable IPv4, while `RemoteIdentifier` remains `vpn.hypervault.biz`. If provider NAT exists, do not bind an unassigned public address. Ensure both ports use the same local IP. Set the conflict-free address range/DNS/ownership values. Authentication and PoC are separate opt-ins; no insecure lab fallback exists.

5. Install the reviewed `ikev2d` release binary, [cleanup_xfrm.py](../tools/poc/cleanup_xfrm.py) as `/usr/local/libexec/harbor-cleanup-xfrm.py`, and [service template](../tools/poc/ikev2-iphone-poc.service). Use a static nonlogin `ikev2lab` system user/group. Keep installed code/config root-controlled. Run `systemd-analyze verify` on the unit before starting. The service runs nonroot with only CAP_NET_ADMIN and CAP_NET_BIND_SERVICE, not unrestricted root. CAP_NET_ADMIN is still broad within the host network namespace; this PoC uses a separate adapter crate, not a separate privileged process. No `PrivateNetwork=yes` because it must configure the host XFRM namespace. systemd `LoadCredential` reads root0600 originals; the daemon validates read-only copies under `/run/credentials`. systemd 255 may use root-owned directory mode 0550 and file mode 0440 with a named service-UID POSIX ACL. The loader verifies that ACL grants no group/other access and actually opens and reads every credential as the service user. Owner-only 0500 directories and 0400 files are also supported. Do not chmod the copies or change service privileges.

## Scoped networking (operator only)

The commands below are examples to review and run on the approved host, never automatic deployment. `network.py` prints a preview unless `--apply` is supplied. Replace `eth0`, `LOCAL_IPV4`, `PHONE_EGRESS_IPV4` with actual values, not literals. Use the phone's current Wi-Fi/cellular **public IPv4**; changing networks requires a reviewed update and reconnect (no MOBIKE).

```sh
python3 tools/poc/network.py setup --wan eth0 --server-ip LOCAL_IPV4 --phone-ip PHONE_EGRESS_IPV4 --subnet 10.77.0.0/24
sudo python3 tools/poc/network.py setup --wan eth0 --server-ip LOCAL_IPV4 --phone-ip PHONE_EGRESS_IPV4 --subnet 10.77.0.0/24 --apply
sudo systemctl daemon-reload
sudo systemctl start ikev2-iphone-poc.service
```

The script creates only dedicated chains and narrow jumps: source-restricted INPUT UDP500/4500, IPsec-policy-matched IPv4 forwarding for the VPN subnet and MASQUERADE for that subnet on the chosen WAN. It rejects unprotected forwarded traffic using the VPN subnet and enables only `net.ipv4.ip_forward`. It does not reset firewall/default policies or touch unrelated NAT. It records successful operations and the previous forwarding setting in root-only `/run/harbor-iphone-poc`. Check any cloud firewall separately; **no cloud/VPS firewall changes are authorized automatically**. On native nftables or mixed firewall setups, inspect ordering before applying: an independent later drop chain can still block traffic; do not flush it to make the PoC pass.

The source-restricted example is intended for a phone behind IPv4 NAT using ESP-in-UDP. Plain ESP is implemented in XFRM, but a direct non-NAT client additionally needs a narrowly source/destination-restricted protocol50 INPUT allowance reviewed by the operator. No such extra rule is silently added. UDP keepalives are handled by the kernel socket path. Check `ss -lunp` and service logs; missing credentials/capabilities or certificate failure must prevent serving. The process does not configure host forwarding/NAT itself.

## iPhone configuration

Transfer the reviewed unsigned [iphone.mobileconfig](../tools/poc/iphone.mobileconfig) by a trusted method and install it in Settings > General > VPN & Device Management. It contains no password, trust anchor or client certificate. Use the disposable password interactively. The profile selects IKE AES-256-GCM/SHA256 PRF/ECP19 and ESP AES-256-GCM, MTU1280, disables MOBIKE/redirect/PFS-for-rekey and does not enable On Demand/Always On. Initial CHILD keys still derive from the authenticated IKE DH exchange. The profile's SHA2-256 field does not enable a separate IKE/ESP integrity algorithm with GCM. Inspect actual native offers rather than assuming the profile was honored.

Manual equivalent: Type **IKEv2**, Server **vpn.hypervault.biz**, Remote ID **vpn.hypervault.biz**, Local ID **m3-disposable**, User Authentication **Username**, Username **m3-disposable**, password entered interactively, Proxy **Off**. A profile is preferred to pin proposals and disable mobility. Standard certificate-authenticated responder EAP is used: profile AuthenticationMethod=None means no client machine authentication; the server still sends certificate/signature AUTH. RFC5998 is not implemented.

Test on an IPv4-only test network first. This PoC negotiates **IPv4 full-tunnel selectors only**; it does not protect or suppress the phone's IPv6 traffic. Do not describe it as a leak-free all-protocol VPN, enable IncludeAllNetworks to pretend IPv6 works, or disable shared VPS IPv6 services. IPv6 support/leak prevention needs a separate decision/test.

## First connection and evidence

- Record exact iOS build, Ubuntu/kernel/OpenSSL versions and tested source revision/hashes. Optional root-only capture: `sudo timeout 90 tcpdump -i eth0 -nn -s 0 -w /ROOT_ONLY_DIR/iphone-poc.pcap 'host PHONE_EGRESS_IPV4 and (udp port 500 or udp port 4500)'`. Captures remain sensitive even though EAP is encrypted. No key logging/decryption dumps.
- Connect; verify INIT suite selection, responder certificate trust, EAP mutual completion and **final AUTH**, then CHILD installation. EAP Success alone never installs a CHILD. Logs show static state names and active CHILD count, not username/keys/payloads. Bounded samples can omit transitions. Do not run ordinary `ip xfrm state` into reports: it prints keys. Use `ip xfrm state count`, `ip xfrm policy count` and private operator tooling that strips key fields before reporting.
- Confirm assigned IPv4 from the configured range and DNS from configuration. On iPhone, visit an IPv4-only public-IP endpoint and an HTTPS site; observed IPv4 egress must equal the VPS's Internet egress. Verify DNS queries/routing using approved operator diagnostics, and test TCP/page loading as well as a small packet. NAT/firewall/MTU behavior is not established by the local UDP test.
- Disconnect; CHILDs/policies must disappear. Reconnect three times with no orphaned resources or address collision. Wrong password and wrong Remote ID must fail with no CHILD. SIGTERM/service stop must clean owned resources. A short test should finish well before the 30-minute hard lifetime; automatic rekey and MOBIKE are intentionally not implemented. If changing Wi-Fi/cellular, reconnect rather than expecting migration.
- Failure to validate a suitable public certificate, missing SHA256/RFC7427 offers, differing native EAP/CP/TS behavior, packet loss from certificate IP fragmentation or target provider restrictions is a blocker to report with sanitized evidence. No trust/AEAD/authentication check may be disabled to force connection.

## Stop, cleanup and rollback

```sh
sudo systemctl stop ikev2-iphone-poc.service
# ExecStopPost reconciles only the reserved reqid range. Preview if needed:
sudo python3 tools/poc/cleanup_xfrm.py --reqid-start 65536
sudo python3 tools/poc/cleanup_xfrm.py --reqid-start 65536 --apply
# Remove only setup's recorded rules/chains; preserve the shared forwarding setting:
sudo python3 tools/poc/network.py cleanup --apply
# If setup enabled forwarding from 0, and no other service now needs it:
sudo python3 tools/poc/network.py cleanup --apply --restore-forwarding
```

Do not run cleanup concurrently with the daemon or another owner of that reqid range. The service uses bounded exclusive creation and ACKs, records only its own successful creates, removes policies before states and releases the address after resource teardown. SIGINT/SIGTERM run Drop cleanup. SIGKILL/power loss or a lost netlink ACK can leave resources; kernel hard lifetimes bound them and ExecStopPost/operator reconciliation removes only ESP states and policies with the reserved reqids. Never use `ip xfrm state flush` or `policy flush`. A boot has empty kernel state; `/run` rule journals are not persistent firewall configuration.

If a rule was externally removed or cleanup fails, stop and inspect the journal rather than deleting an entire chain or firewall. Removing a named chain that another administrator has since modified intentionally fails. Keep forwarding enabled if other services rely on it; the second cleanup command restores the prior0 only after explicit operator dependency review. If forwarding was already1, it stays1. No default route/DNS/SSH/nginx/SSTP/mail/Docker configuration needs rollback because these tools do not change it. Remove the iPhone profile and retire disposable verifier/key/capture material under the operator's retention policy. Disable/remove the service only after cleanup.

References: [RFC7296 CHILD key derivation, selectors, configuration and deletes](https://www.rfc-editor.org/rfc/rfc7296.html), [RFC4106 ESP AES-GCM](https://www.rfc-editor.org/rfc/rfc4106.html), [Apple IKEv2 profile schema](https://developer.apple.com/documentation/devicemanagement/vpn/ikev2-data.dictionary).

## Credential-loader fix: rebuild and deploy

systemd 255 [documents protected credential copies](https://www.freedesktop.org/software/systemd/man/255/systemd.exec.html#LoadCredential=); its [implementation](https://github.com/systemd/systemd/blob/v255/src/core/exec-credential.c) prefers named-UID ACLs and falls back to ownership. Group mode bits on ACL-backed files describe the ACL mask. A plain group-readable file without the restricted ACL is rejected.

From the repository root, build on the Ubuntu 24.04 host with the project's Rust toolchain:

```sh
cd src
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test -p vpn-auth -p ikev2d
cargo build --release --locked -p ikev2d
cd ..
```

Optional privileged regression with synthetic data only (requires `acl` and `util-linux` packages). Locate the test executable and run the fixture as root; it invokes the Rust test as your ordinary nonroot UID, with supplementary groups cleared:

```sh
cargo test --manifest-path src/Cargo.toml -p vpn-auth --lib --no-run
# Set TEST_BINARY to the vpn_auth executable printed by the preceding command.
sudo python3 tools/poc/check-credential-layout.py "$TEST_BINARY" "$(id -u)"
```

Deploy only the replacement binary to the existing installation; the unit, credential originals and firewall stay as configured. Stopping/restarting disconnects active VPN sessions and runs the existing unit cleanup:

```sh
sudo systemctl stop ikev2-iphone-poc.service
sudo install -o root -g root -m 0755 src/target/release/ikev2d /usr/local/libexec/ikev2d
sudo systemctl start ikev2-iphone-poc.service
sudo systemctl is-active ikev2-iphone-poc.service
sudo journalctl -u ikev2-iphone-poc.service -n 50 --no-pager
```

Successful startup verifies actual reads of all four credentials inside the unit's execution context. Checking with `sudo -u` outside that context does not reproduce its credential mount namespace. Do not print credential contents. The root-owned fixture and actual systemd service startup still require verification on the target host if unavailable in the development environment.
